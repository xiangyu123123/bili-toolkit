站主登录

登录后这一页会多出后台：反馈全文列表、逐条删除、导出 JSON。游客只能提交，看不到任何一条。

一个脚本，五个可独立开关的模块

装好后在任意 B 站页面点右下角的 B+ 圆钮（或按 Shift+X）打开控制台：左边选模块、右边调参数，每条净化规则和弹幕/评论都会显示本页实时命中数，一眼看出它到底有没有在干活。圆钮和面板都能拖动，位置会记住。

安装脚本 下载 .user.js 文件

点「安装脚本」没弹出管理器安装页时：先装管理器，或用「下载文件」再把文件拖进管理器的「实用工具 → 导入」。 部分浏览器/管理器需要在设置里打开「允许用户脚本」并授予本站访问权限。

  • 版本 1.6.1
  • 生效范围 www / t（动态）/ space / live 桌面端 · 规则按站点分别生效
  • Tampermonkey ✓
  • Violentmonkey ✓
  • 需要 GM_setValue
  • 不含任何远程依赖

装之前要知道的三件事

  1. 它会改页面 DOM 和播放器倍速，属于「自己页面上的自定义」，不绕过会员、不抓取数据、不下载视频流。
  2. 视频线路测速与选线默认是关闭的，需要你主动勾选，因为它会介入播放地址的选择；打开后也是你自己在测速表里点「用这条」，脚本不会替你决定。
  3. B 站改版会让部分 CSS 选择器失效。脚本内置了「拾取要隐藏的元素」模式，你可以自己点掉想隐藏的东西，不依赖我猜的选择器。

拾取模式（最耐用的一条路）

面板里点「拾取要隐藏的元素」→ 面板自动收起 → 鼠标移到目标上出现粉框 → 点一下：元素当场消失，路径写进「自定义选择器」。Esc 取消。

生成的路径最多四级，优先 #id，其次前两个类名，都没有就退化到 :nth-of-type()。

限制

  • 子串匹配可能误伤（某块区域整体类名里含 live-card）。取消那条勾选即可恢复。
  • :has() 需要较新的浏览器；不支持时推广卡那条会退化为只隐藏链接本身。
  • 只是不显示，资源仍会请求；不是广告拦截器，也不影响 UP 主收益结算。
  • 「恢复默认设置」会连你拾取的规则一起清掉。

播放增强 默认开启

直接操作 <video> 元素的 playbackRate / volume / currentTime，并在播放器右上角挂一条悬浮工具条。

  • 倍速：范围 0.1–上限（默认 5，可调到 16），步长 0.25；「记住并恢复倍速」在换 P、换清晰度后自动回填。
  • 跳过片头 / 片尾：以「秒」为单位。播放中按 Shift+I 记录片头结束点、Shift+O 记录片尾提前量，或直接在面板里填数字。
  • 播完自动连播：优先点播放器自己的「下一 P」按钮，找不到就按 __INITIAL_STATE__ 的分 P 列表跳转。
  • 音量微调：, . 每次 ±2%（步长可改）。
  • 自动最高画质：档位从三处取并集 —— 页面内嵌 __playinfo__.data.support_formats、播放器 getSupportedQualityList()、画质菜单 li[data-value]（菜单是播放器自己那次 fnval=4048&fourk=1 请求渲染出来的，最接近你实际能点到的档）。取并集里的最高档后调 player.requestQuality()，轮询 getQuality().realQ 确认真切过去了才报成功；这一档切不过去就逐级退回次高一档并说明是哪档拿不到，退到不高于当前档就不再退、如实显示「未生效」。绝不自己拼 quality 数值去试账号墙外的清晰度。实测：网页端 4K 是 qn=120（菜单文案「4K 超高清」），不是常说的 116；未登录时 requestQuality(120) 会被静默接受但 realQ 不动 —— 所以「确认 + 降档」是必须的。
  • 悬浮工具条：只有 5 个控件 —— 倍速 −/当前值/+、弹幕开关、⋯ 展开的二级菜单（设片头、设片尾、复制时间戳、线路测速、打开设置）。实测过：九钮一排会占掉播放器顶部 473px，压到画面上；收窄后是 206px。鼠标进入播放器出现，离开淡出；展开二级菜单时会钉住不消失。

限制

  • 超过 B 站菜单上限的倍速靠 playbackRate 硬调，浏览器可能在高倍速下丢帧或不同步音轨，属正常现象。
  • 工具条需要找到播放器容器（#bilibili-player / .bpx-player-video-wrap / .bilibili-player-video-wrap / #mplayer）。找不到时倍速快捷键仍然可用，只是没有悬浮条。
  • 片尾跳过是把进度推到最后一刻，若你开了 B 站自带的「播完推荐」，行为会和它抢。

观看干扰屏蔽 默认开启

专治看着看着弹出来的东西：点赞/投币/收藏/关注/充电/试看这类引导提示条，以及播放器内的关注引导层和进度条弹窗。开关在控制台的「播放增强」页底部单独一组。

两条通道

关键词挡提示条：B 站播放器里的浮动引导都走同一套 toast 组件（实测容器 .bpx-player-toast-item，文字在子节点里）。脚本按关键词命中就把这一条 display:none，默认词表：点赞 / 投币 / 收藏 / 关注 / 充电 / 试看 / 大会员 / 免费。

直接屏蔽引导层：实测存在的 .bpx-player-top-follow、.bpx-player-follow（关注引导）、.bpx-player-progress-popup（充电弹窗）用样式表常驻隐藏，不依赖它什么时候出现。

为什么不是「全关掉」

同一套 toast 也用来播报「网络异常，正在重试」这类有用的信息。所以默认只按关键词挡；想全挡就开「连所有提示条一起隐藏」，代价是故障提示也看不到了 —— 界面上把这层取舍写明了。

限制

  • 关键词是纯文本包含匹配：如果某条正常提示里刚好出现「收藏」二字（例如 UP 主自定义的提示），它也会被挡掉。
  • 三连引导只在特定时刻出现，本次会话里没等到它；已验证的是同一 toast 机制上的「登录 免费享高清视频试看30秒」和三个引导层被隐藏。若 B 站把引导换成别的组件，这一组会失效，但屏蔽徽标会显示「当前无弹窗元素」而不是假装在工作。
  • 挡的是页面显示，不会去点掉、也不会阻止账号状态变化；该给三连还是该给三连由你决定。

素材提取 默认开启

只在视频页（/video/BV…）有内容，读的是页面自己带的 window.__INITIAL_STATE__，不发额外请求。控制台「素材提取」页给出：

  • 标题、BV 号、aid、发布时间、分 P 数量；
  • 封面原图直链（已剥掉 @… 尺寸后缀）：复制直链 / 下载封面；
  • 分 P 列表，每行一个「复制直达」按钮（带 ?p=）；
  • 「复制本页链接」和 Shift+T 的当前时间戳链接（?p=1&t=秒）。

限制

  • 下载封面走 fetch → blob，若图床不允许跨域读取会自动降级成「新标签打开原图」并提示你。
  • 不提供视频流（m4s/mp4）下载，也不提供分 P 批量抓封面。

弹幕评论 默认开启

弹幕

现网桌面端的弹幕是 DOM 节点（.bili-danmaku-x-dm 这类，挂在 .bpx-player-row-dm-wrap 等层里），不是 canvas。所以做法是：给命中的节点直接加 display:none，而不是去拦 fillText。

两条通道：关键词命中单条不显示；Shift+D 或面板开关把整层弹幕容器（render/row/adv/bas/cmd 五种 wrap）一起隐藏。

面板里有一个 已屏蔽 N 条 的实时计数，为 0 时写「当前无命中弹幕」—— 这个环境里 B 站不给未登录账号下发弹幕，就能看到它到底是「没命中」还是「没弹幕」。

评论

对 .reply-item 做关键词高亮（<mark>，跳过已有链接和已标记文字），命中且开启「自动折叠」时给评论加模糊，点一下展开。

懒加载的新评论由一个 400ms 防抖的 MutationObserver 重新扫描。面板同样显示「本页 N 条 / 折叠 M 条」，评论区还没渲染出来就写「未找到评论元素」。

限制

  • 弹幕屏蔽依赖 B 站继续用 DOM 渲染弹幕。若某次改版换成 WebGL 画布，这套选择器会失效 —— 判断方法就是看那个实时计数是否一直是 0。
  • 屏蔽是本地不显示，不影响服务端弹幕数据，也不会让你发的弹幕被别人屏蔽。
  • 评论区需要页面自己渲染出来（未登录或没滚到评论区时没有 .reply-item），此时高亮与折叠无从生效，面板会直接告诉你。

线路测速、选线与 PCDN 阻断 默认关闭

就是「禁用 PCDN + 一键调用最快的视频服务器」，但决定权在你：脚本把播放器这次拿到的全部地址列成一张表，你测完自己点「用这条」。

怎么用（三步）

  1. 勾选「启用」→ 播放一次或切一次清晰度。脚本同时从页面自带的 window.__playinfo__ 和之后的 /x/player/wbi/playurl 响应里收集候选地址；对 __playinfo__ 只观察不改写（播放器已经消费过它，改写没收益，还会让表格看不到 PCDN 候选）。
  2. 点「开始测速」。表格按主机聚合（实测一个视频给出 27 条地址但只有 17 个主机，按地址排会满屏重复），每个主机只测一次：取它承载的最高带宽那条流发一次 Range: bytes=0-262143 的 GET，2.5 秒超时、3 路并发、一轮最多 12 个主机。能跨域读 body 的给出 延迟 + Mbps；只回 opaque 响应的退化为 仅 RTT；不响应的标 超时 / 失败。跑完按吞吐降序排列，最高的一行标「· 最快」。
  3. 点某行的「用这条」→ 主机写进 cdn.pin → 点「重载播放器」或切一次清晰度。之后每次 playurl 响应里，这个节点都被排到列表第一位，其余地址保留作回退。

锁定优先于自动排序：你选的节点哪怕慢、哪怕它本身是 PCDN，也会被保留并排到最前。「清除锁定」回到自动规则；「按实测延迟自动排序」关掉后就只认你的锁定。

怎么判断一个节点是不是 PCDN

光靠主机名不够：实测 B 站给的 P2P 节点既有 xy…x.mcdn.bilivideo.cn:8082，也有 ….edge.mountaintoys.cn:4483 这种完全不在常见命名规律里的。所以脚本另加一条启发式 —— 非标准端口即视为 PCDN（常规 CDN 走 443/80，P2P 走 :8082、:4483）。这条可以单独关掉，端口本身也显示在节点列里，方便你自己判断。

关键一条：B 站把 PCDN 放在主地址，正规 CDN 藏在备用

实测 dash.video[].base_url 给的是 xy<ip>xy.mcdn.bilivideo.cn:8082 这类 peer 地址，而 upos-sz-* / cn-sxxa-* 这些正规节点只出现在 backup_url 里。所以「剔除 PCDN」如果按字面删条目，会把整条流删空 —— 脚本的做法是把第一条非 PCDN 的备用提升为主地址，剩下的备用照旧保留。提升后如果某条流实在没有可用备用，才保持原样（不断流优先）。

改完后分片请求的 os= 参数会从 mcdn 变成 coso1bv / hwo1bv 这类正规 CDN 标记 —— 这是判断有没有真的离开 PCDN 最直接的证据。

阻断 P2P 调度会话

你关心的「偷上传」：浏览器不能监听端口，peer 没法直接从浏览器拉数据，所以 Web 端参与 P2P 的通道只有那条 wss://…player-tracker…socket.io?…sdkVersion=2.14.0%3Aleecher 会话（leecher 就是 P2P 客户端角色）。实测这一页全程没有任何 WebRTC / datachannel。脚本把命中的 WebSocket 构造换成一个立即 error/close 的伪装对象（仍满足 instanceof WebSocket，不会让 SDK 崩），引擎就既拿不到 peer、也无处共享。

  • 只匹配 player-tracker / leecher / pcdn / pdl / p2p；实测聊天广播那条 wss://broadcast.chat.bilibili.com:7826 原样放行，不受影响。
  • 面板底部会显示「已拦截 P2P 会话 N 次」，线路页的徽标能看最近一次被拦的地址 —— 不是装了个没有作用开关，是能看到它在挡。
  • 模块关闭时完全不拦截任何连接。
  • 诚实边界：这能确定断掉的是浏览器侧的 P2P 参与。若你用的是 B 站桌面客户端，它的 PCDN 不在这个脚本的能力范围内。

边界与限制

  • 锁定不一定改得到线：B 站按清晰度和区域下发节点，你锁定的主机可能不在下一次响应里。这时表格下方会直接写「锁定的 X 不在本次地址表里，所以这一次不会改线」，而不是假装生效。
  • 并发测速会互相抢带宽，绝对数值有噪声（同一主机不同流能差出一倍）。它够用来排序，但不是严谨的带宽测试。
  • 只在本次响应给出的地址里选，不枚举、不扫描 B 站没给你的节点；测速是你点一次按钮才发一轮，脚本不会自己反复压测。
  • 关闭本模块时脚本完全不读取、不解析、不改写任何请求；开启后候选地址表也只存在内存，重载页面即重新采集（持久化的只有你的锁定主机和测速延迟缓存）。
  • backup_url 里命中特征串的备用地址会一并剔除；但如果某条流的所有地址都命中，就保持原样不动 —— 宁可继续走 PCDN，也不让播放器拿不到地址。
  • 锁定对之后的请求生效：切清晰度、切 P、重载播放器。刚点完不重载是看不到变化的。
  • 吞吐数值依赖节点允许跨域读体（带 Range 的 GET）。不少 CDN 只回 opaque 响应，此时只能比 RTT，比不了实际带宽 —— 表格里会明确标出来。
  • 开代理/加速器时测出的是代理链路质量，未必等于播放器真实体验。

外观与主题 默认跟随 B 站

三套主题 + 自定义强调色

面板新增「外观」页：跟随 B 站（默认）/ 浅色 / 深色，外加自定义强调色和面板不透明度（60%–100%）。改完立刻生效，不用刷新。

「跟随 B 站」不是去猜它当前是深色还是浅色：B 站自己在 :root 上发了一整套设计变量，实测能读到 --bg1_float=#FFFFFF、--bg2=#F6F7F8、--text1=#18191C、--text2=#61666D、--line_regular=#E3E5E7、--brand_pink=#FF6699、--brand_blue=#00AEEC。面板配色直接引用这些变量，所以它切深色模式面板跟着切，颜色也不用我猜。

强调色留空就用 B 站的 --brand_pink；自己选一个十六进制色会覆盖到开关、选中项、悬浮球角标、徽标和进度条上。

限制

  • 只改面板，不改 B 站页面。弹幕、顶栏、信息流配色一律不动 —— 那是 B 站自己的主题，改了容易和它的深色模式打架。
  • 播放器右上角那条小工具（倍速 / 弹幕 / ⋯ 二级菜单）同样跟随主题：它压在画面上，所以靠 1px 描边加投影和画面区分，不再固定深色。
  • 「跟随 B 站」依赖上面那套变量存在。若某类页面没下发（比如 B 站改版），会退回每档的兜底色值，不会出现白底白字。
  • 不透明度用的是 color-mix()（Chromium 111+）。低于 100% 时面板会透出底下的内容，滚动时文字会有点花，默认 100%。

数据存储

所有开关、倍速、片头片尾秒数、关键词、自定义选择器和测速缓存都写在一个键 btk.cfg.v1 下，优先用 GM_setValue（扩展存储，跨标签共享）；管理器不提供 GM 存储时自动退到 localStorage。 控制台「关于」页的「恢复默认设置」和管理器菜单里的同名命令会清掉这个键。没有服务端、没有上报、没有任何第三方请求。圆钮和面板的位置也存在同一个键下，拖动后会自动记住。

常见问题

装了以后页面上没有 B+ 圆钮

依次检查：管理器里该脚本是否已启用、是否给了 www.bilibili.com 的访问权限、地址是不是桌面端（m.bilibili.com、live.bilibili.com 不在 @match 内）。都正常就硬刷新一次（Ctrl+F5），脚本在 document-start 装载，旧标签页不会自动生效。

隐藏了不该隐藏的东西 / 想临时恢复

面板 → 界面净化 → 取消对应分组勾选，或删掉「自定义选择器」里那一条。display:none 只存在于运行时注入的样式表里，不修改你的账号设置。

弹幕关键词没生效

先看面板「弹幕评论」页里的那个徽标。写「当前无命中弹幕」有两种可能：真的没命中，或者这个页面此刻根本没给你下发弹幕（未登录、或该时间点没有流量）—— 这两种状态在界面上分不开，因为脚本只能看到 DOM 里有没有 .bili-danmaku-x-* 节点。若徽标有数但你确定关键词该命中，说明 B 站把弹幕渲染换成了画布，此时 DOM 屏蔽失效，只能用 Shift+D 整层隐藏。

测速表里是空的 / 全是「待测」

地址表是从 playurl 响应里现采的：刚勾上「启用」时脚本还没机会读到响应，点「重载播放器」或切一次清晰度就会填上。「待测」是你还没点「开始测速」；测完之后按节点能力分别显示 Mbps、仅 RTT 或失败。

开了线路模块后播放报错 / 黑屏

先在面板里取消勾选「启用」，再点「重载播放器」。这个模块介入的是播放地址的选择，出问题时的正确退路就是关掉它。也可以只关「剔除 PCDN 地址」而保留锁定，用来定位是不是备用地址被剔掉导致的。

为什么线路优选要默认关闭

它会改写播放器拿到的响应，是五个模块里唯一改变「内容从哪里取」的一个。界面净化、倍速、素材、弹幕评论都只影响你这台设备的显示与操作，所以默认开着。

会不会影响 B 站风控 / 封号

脚本不自动发送弹幕、不签到、不点击任务、不做批量请求，测速上限是每次响应最多 6 个主机各一次 HEAD。它仍然是一段在页面上执行的非官方脚本，是否使用由你自己判断。
